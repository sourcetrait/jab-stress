# consumers.nuon

The readers of landed runs and the inputs each requires, which `runner
record required` holds a restoration to. The table names the rereads that
read through a restoration today: the sdl probe's controls reread, which
requires the controls' record and the monolithic control's shim log and
flush trace. Its other inputs, the modular and stripped controls' logs, are
read where they are there, so they are not required. ProbeRuns' reader,
`fps proberuns`, requires a batch's report and each run's capture,
identity, route, and bundle manifest, at any depth under the tree, so a run
landed as one battery or as several reads alike. walk's readers take three
names: `kernel walk guest`, a set's runs read guest-only, each run's stream
and identity at any depth; `kernel walk paired`, a probed run read paired,
its bundle's manifest, stream, identity, shim log, and classification; and
`kernel walk launches`, the CADENCE_TEST launches' recorded cases, each
case's stream and identity under `runs/` and the replay's stream beside
them. The footprint reader's reread, `fps footprint`, requires each view's
capture record, each launch's screen, stream, and UART log, the still
copies' disk records, the images' record, and the first reading. Each reader
that comes to read through a restoration adds its rows here.
