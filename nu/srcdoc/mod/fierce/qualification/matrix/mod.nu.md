# mod.nu

The qualification's matrix and what its parts share: the targets, the map every
run plays, the record's file, the cases a bench run holds, the diagnostics read
from the normal play runs, every other final obligation, the packaged bench, the
acceptance's rules, a run's agreement with the
candidate and its conditions against its step, its verdict, and the ledger and
its two verdicts, which the record writes and the check derives again, and the
helpers the candidate, the record, the check, the report, and the package all
read, jab's checkout and the workbench's among them.

## const JAB

jab checked out beside this repository, and this repository

## const TARGETS

the qualification's targets, each a named spec (the matrix)

## const MAP

the map every run plays

## const RECORD

the record's file in its directory

## const CASES

The matrix's cases a bench run holds: each its kind, acceptance,
diagnostic, or control; the reading it takes, every run's verdict, the
service's verdicts with each window (SceneOwnership's steady load on
1KB1), the refusal (the feature unavailable on 1KA1), the audio's debug
runs (RegressionSuite's play with live sound), the presentation
(ProbeRuns' reader over the probed runs), the shim control (observer.nu),
or the scaling control; each target's steps; and why a target holding
none of a case's steps leaves it not applicable.

## const AUDIO_WORDS

The QEMU words the audio's step carries, gauge/audio's trace of the
reports QEMU drops, which its runs' identities record as their own.

## const GFX_FLOOR

The service's start refused under the floor, the take's GFX_FLOOR, the
feature unavailable's answer on 1KA1.

## const DIAGNOSTICS

The diagnostics read from the normal play runs' own frames (the matrix's
diagnostic rows): each its route legs, every leg a run holds where it
names none, and the fields of a leg's summary (gauge/measure's leg-summary).

## const OBLIGATIONS

Every final obligation no bench carries (ObligationLedger): the
correctness runs and the suites at the freeze, his Linux host's bench
(U1), the Windows runs (U4), and the reports with the evidence package;
each a state and a ground by target, pending on its dependency or not
applicable for its reason, his ruling where one stands; and `met_by`, the
bench that meets it where a bench can, its machine's declared role and
the OS it runs, the Linux host's a Linux desktop's (U5, DeclaredConditions).

## const UNMEETING

Why a bench's runs meet no obligation, by its machine's declared role
(DeclaredConditions): `unknown`, a machine declaring none, every landed
bench recorded before roles among them, and `metal`, whose runs are Jab
Metal's, which this qualification holds no obligation of. A `container`
bench supports the preparation subset and a `desktop` bench meets U5's,
so neither is here.

## def step-verb

The gauge's verb in a step's words, the first `play`, `run`, or `audio`
after the script: the bench files before JustToNu named `test/gauge.nu
play`, after it `nu/bin/nuance.nu gauge play`, so the verb's place moved
and a fixed index read the script's next word as the verb.

## def role-of

The named build a step's words run, the first `{build:<name>}` in them,
null for the tree's own build; read from the candidate's definition
before its words are resolved.

## const PACKAGED

Where a package lays each guest input a packaged step takes, by role.

## def packaged-bench

The candidate's bench as its host package runs it (HostPackage): the
preflight first, a gate, then every step of the candidate's bench file
with the package's image, kernel, and asset tree named, a step naming its
own image, a named build's, keeping it and taking the asset tree alone, a
route run with the package's route, `build: none`; `{package}` stands for
where the package is extracted and `{build:<name>}` for the package's
`build/<name>`, both filled by the bench module. The package's maker
writes it and the record holds a packaged run to it, so both read the
one transform.

## def resolved-in

A bench's definition as a run of it read its words: `{package}` the
package's directory, and each `{build:<name>}` that build's directory
under `root`, the `build_root` the run's bench.nuon records, so the
record compares the words that ran with the definition's.

## def flag-of

The value after a flag among a step's words, null where it is absent.

## def sha-of

A file's SHA-256, null where there is none.

## def jab-file

A file of jab's at a commit, its text, null where the commit holds none.

## def ms

Milliseconds to a tenth from microseconds, a dash for none.

## def short

A commit shortened for reading.

## def same-commit

Whether a commit as an identity records it, shortened or whole, is the
candidate's.

## def build-of

The build a step's runs are held to: the candidate's release build, or
the named build its words run, the candidate's record of it, with its
tree and the QEMU words its step carries, the audio's AUDIO_WORDS and
none for any other; a named build the candidate records none of is its
problem.

## def agreement-of

Where a run's identity disagrees with its build, the candidate, and the
target, each disagreement named: the image's, the ELF's, and the kernel's
SHA-256, its build's (build-of); the assets' map and digest; the
workspace's and the program's commits and their changes; the machine, the
target's named spec with its cores, RAM, and display, never a custom
machine; QEMU words but its step's own; the cap, the target's frame rate;
and its build's tree.

## def finite

An int is finite; a float is finite unless its text is `inf`, `-inf`, or
`NaN`. The text, since nushell 0.115.1 compares every finite number equal
to `inf`: `1.5 == inf` reads true and `1.5 < inf` false, so a guard
written against `inf` refuses every finite value.

## def conditions-of

Where a run differs from its step's declared conditions (RederivedChecks),
each named: the service at the step's `--service` quota or none, the
workers automatic or forced to the step's count, the cadence the step
asks or the gauge's default 1, none for the audio's play, the window and
the sound live with `--host` or a play and off and recorded otherwise, the
audio's `--host` sound live on a machine declaring `desktop` alone and
recorded on any other, since gauge/audio records where the machine has no
output and the declared role carries the machine's audio
(DeclaredConditions), the
pad the route's, the host's for a play, or the table for the audio's, and
the sdl probe on the probed steps alone. A run that differs is foreign to
its case, so it fails an acceptance case and leaves a control unmet.

## def tag-state

The freeze's tag resolved in jab against the candidate's commit: met when
`qual/<n>` names it, failed when the tag is missing or names another,
pending for an untagged candidate, since no freeze stands. jab-stress's
own commit and tag are the readers' provenance and never judged.

## def service-problems

Why a run cannot certify the steady service load (SceneOwnership), each
named: its capture holding no service record, its image no SERVICE
build's; its start never answered or refused; other than one window
closed; and any quota skipped, a reduced load reported at its offered
rate. A window's own breaks, conservation, the chains, and the gaps, stand
in the run's standing, its measurement invalid.

## def verdict-of

An acceptance run's verdict (Qualification.md's acceptance): it passes
when it stands valid, holds a play median, a finite median over its valid
play window, its identity agrees with its build and the target, its
conditions are its step's, with `--service` its service admissible
(service-problems), and its critical path's median is under the ceiling
by `gauge report under-ceiling`, the one rule; a valid run with no finite
median fails, "no play median", never passing by absence; every problem
named; the median and the tail beside it.

## def run-name

A run named for reading.

## def case-problems

A case's problems from a record: an acceptance case's missing and
reseeded runs and each run's verdict's problems; a control's reseeded
runs and its reading's problems when unmet; the presentation's reseeded
runs and its reading's problems when unread.

## def diagnostic-problems

A diagnostic's problems from its reading: no normal play route run to
read, and each leg a run lacks.

## def admissibility-grounds

Why a control's probed readings are inadmissible (LedgerAdmissibility),
from its reading: each measure measured past its noise, its two arms'
statistics, the effect, and the noise in microseconds (on the 1KA1
preparation proof, the flip median 1651 us probed against 1601 plain, an
effect of 50 against a noise of 22); then each measure the observer could
not evaluate, by the observer's own problems naming its missing input
(the reading's `unevaluated`), never as a measured noise failure.

## def ledger-of

The ledger (ObligationLedger): every final obligation on the record's
target a row with its kind, whether the bench carries it, its state, its
admissibility, its evidence, its ground, and its problems. The bench
carries its cases, its diagnostics, and its own agreement with its
definition, `held` naming every problem of the bench, its conditions, and
its reopened inputs; the freeze's tag is tag-state's; every other
obligation OBLIGATIONS'. A case whose steps the target holds none of is
not applicable, its CASES reason its ground. The presentation's row is
met only where ProbeRuns' reader read every probed run, never a bundle
directory's presence. A control's row carries `admissible` as its reading
gives it, the shim control's true or false, since Qualification.md admits
the probed readings only on a passing shim control of their scope, and
null for a control with no admissibility of its own and for every other
row, so no control gains a pass condition; an inadmissible row's `why` is
its grounds (admissibility-grounds), whatever its state. The bench's
declared role (bench-role) then decides what its rows meet: a bench whose
role UNMEETING names leaves each row it carries that would be met pending,
its `why` that reason with an inadmissible row's grounds after it, its
readings kept and its failures failed; an obligation whose `met_by` names
the bench (meets) is the bench's to meet (met-by-bench); every other
obligation stands as OBLIGATIONS gives it. The verdicts read the states
alone.

## def bench-role

A record's bench role: its runs' one declared role, the conditions'
`roles`, else `unknown`, for a bench of mixed roles, which the conditions
name a problem, and for one with no run.

## def meets

Whether a bench is the one an obligation's `met_by` names: its declared
role that role and every host its runs record running that OS.

## def met-by-bench

An obligation a bench meets: met when every row the bench carries is met
or not applicable, its evidence the bench, its stamp, its system, and its
role; else failed, naming each row the bench carries that is not.

## def verdicts-of

The two verdicts read from a ledger, kept apart: the preparation subset's,
the rows the bench carries, passing on those alone; and the final one,
"qualification passes" only when every row is met or not applicable, else
"qualification does not pass" naming every failed row, or "qualification
incomplete" naming every pending row with its dependency. The campaign's
completion stays TheUser's acceptance; a verdict says qualification.
